# 장식 효과 최적화 자동 적용

2026-11-09. `MagicPlugin.EnableNetworkCosmeticOptimization` 옵션 제거에 이어, 일반 호환 패치를 클라이언트만으로 사용할 수 있도록 InteropFixes 전체의 필수 설치·버전 검사를 제거했다. 사용자 설정이나 숨겨진 고급 설정은 없다. 기존 cfg에 저장된 ON/OFF 값은 등록하거나 읽지 않는다.

## 실제 적용 조건

고정 ON은 사용자 정책을 뜻하며, 모든 효과의 네트워크 객체 생성을 무조건 생략한다는 뜻은 아니다. 다음 조건은 계속 확인한다.

- MagicPlugin의 관련 코드·프리팹과 효과 수신 기능이 준비되어 있다.
- 현재 플러그인·네트워크·씬이 유효하며, 장식 효과 통신 오류로 중단된 상태가 아니다.
- 게임의 피어 접속 승인이 완료됐고, 현재 연결에 대한 장식 효과 전용 합의가 성립했다.
- 서버와 연결된 참여자들의 준비된 기능 교집합에 해당 기능이 포함된다. 클라이언트는 현재 세션의 서버 허가를 받은 뒤에만 새 최적화를 시작한다.

조건이 충족되지 않은 기능은 원래 효과 생성 경로를 사용한다. 미확인 참여자, 준비되지 않은 씬, 지원 기능 상실과 통신 실패는 계속 허가를 낮춘다. 선택 모드의 부재나 지원 불일치만으로 일반 접속·저장·다른 연동을 막지 않는다.

## 선택 설치와 서버의 역할

VNEI 조회, EpicLoot/AzuCraftyBoxes 저장 연동과 MagicPlugin의 일반 호환 수정은 다른 참여자의 InteropFixes 설치를 요구하지 않는다. 각 연동은 설치된 관련 모드와 실행 역할에 맞게 적용되며, 대상 모드의 자체 설치 요구사항은 바꾸지 않는다.

장식 효과의 네트워크 객체 생략에는 여전히 서버와 관련 참여자의 준비된 지원이 필요하다. 서버가 기능 보고를 모으고 공통 기능만 허가한다. 서버 미설치 시 클라이언트는 Hello·허가를 받지 못하므로 원래 효과 생성 경로를 사용한다. 서버에 설치되어도 미설치·미확인 참여자나 지원 기능이 전혀 없는 참여자가 남아 있으면 합의 허가가 0이 되어 새 생략을 중단한다. 일부 기능만 지원하는 경우에는 모든 참여자가 지원하는 기능만 허가한다. 미설치 참여자의 접속을 차단하지 않는다.

설정 항목이 없으므로 ServerSync 컴파일 참조·병합·초기 동기화 의존성과 완료 훅을 제거했다. `Libs`의 원본 자료와 이전 검사 기록은 이력으로 보존하며 최종 DLL에 포함하지 않는다. 다른 모드가 사용하는 ServerSync나 게임의 접속 정책에는 개입하지 않는다.

## 장식 효과 전용 합의

합의 프로토콜은 2이며 Hello·Report·Grant RPC 이름에 `.v2`를 사용한다. 서버의 연결별 nonce, 세션 ID와 증가하는 보고/허가 revision을 확인한다. 클라이언트는 현재 서버 연결에서 온 Hello를 받은 뒤 준비 상태를 보고하고, 서버는 네이티브 피어 승인과 기능 보고가 모두 확인된 뒤 공통 기능을 허가한다. 알 수 없는 프로토콜·세션·연결·오래된 보고는 허가를 올리지 않는다.

서버는 새 연결에 Hello를 보내지만, 유효한 보고가 없는 참여자에게 Grant를 반복 전송하지 않는다. 응답하지 않는 참여자를 합의 대상에서 제외해 최적화를 강행하지도 않는다. 접속·씬·지원 기능 변화가 준비 보고를 갱신하며 매 프레임 검사나 준비 완료 타임아웃으로 강제 허가하지 않는다. 관련 통신 실패는 새 장식 효과 생략을 중단하고 일반 접속·저장·다른 연동은 유지한다.

기존 v1 구현과 새 v2 합의는 섞이지 않는다. 이전 InteropFixes 바이너리 자체에 남아 있는 필수 설치·버전 검사가 접속을 거절할 수 있으며, 새 DLL이 다른 참여자의 구 코드까지 해제하지는 않는다. DLL 교체에는 재시작이 필요하며 실행 중 교체는 지원하지 않는다.

## 유지하는 수신 경로와 한계

이미 기록된 launch/Nova carrier와 실제로 생략이 완료된 명중·파괴 이벤트의 전달·수신·재생은 새 작업 허가와 독립적으로 유지한다. 씬·참여자·기능 상태가 바뀌었다는 이유로 이미 진행한 효과의 수신을 임의로 취소하지 않는다. 합의 RPC의 세대 변경과 별개로 기존 효과 marker와 재생 이벤트의 식별자·형식은 유지한다.

새 참여자로 인해 서버가 허가를 낮추어도 기존 클라이언트가 이를 받기 전까지 이전 허가를 사용할 수 있는 비동기 구간은 남는다. 선택 설치 전환은 게임 입장이나 ZDO 전달을 막는 원자적 장벽을 추가하지 않는다. 미설치 참여자 또는 서로 다른 프리팹 구성이 겹치는 늦은 접속 상황에서 이미 진행 중인 효과까지 동일한 표시를 보장하지 않는다.

MagicPlugin의 다른 수정, VNEI 조회, EpicLoot/AzuCraftyBoxes 저장 연동은 기존처럼 독립적으로 적용한다. 모드 버전과 배포 형식은 이 변경에서 올리지 않는다. 정적·격리 검사와 실제 게임/서버 실행 검증의 범위는 구분한다.
